# 热迁移前检查清单与影响因素

**日期**：2026-10-29
**适用场景**：KVM/QEMU + libvirt，宿主机 A → B 热迁移（含 `--copy-storage-all` 非共享存储）
**依据**：libvirt Guest migration 文档、QEMU Migration 文档（framework / features / compatibility / best practices）、virsh migrate 手册

---

## 0. 先记住 6 个硬门槛

迁移失败大多数不是“网络慢”，而是下面 6 类之一：

| # | 门槛 | 典型失败现象 |
|---|---|---|
| 1 | QEMU/libvirt 版本、machine type 兼容 | Prepare 阶段就报错，或目标端起不来 |
| 2 | CPU 模型/特性/拓扑兼容 | 数据 100% 后 `loadvm` 失败 |
| 3 | 存储路径/权限/空间/cache mode | 建盘失败、迁移中 I/O 错误、数据损坏 |
| 4 | 管理链路与迁移端口 | 连不上、迁移卡住、NBD 连接失败 |
| 5 | 设备可迁移性（直通/固件/TPM 等） | 目标端设备缺失、状态恢复失败 |
| 6 | 安全（SELinux/证书/加密） | 权限拒绝、TLS 握手失败 |

## 1. 检查清单

### 1.1 迁移管理链路（A → B）

| 检查项 | 命令 | 通过标准 |
|---|---|---|
| SSH 可达 | `ssh -p 55555 root@B true` | 返回 0，无交互提示 |
| libvirt 可达 | `virsh -c 'qemu+ssh://root@B/system?port=55555' version` | 能返回版本 |
| 目标端域列表 | `virsh -c '...' list --all` | 正常返回 |
| 主机名解析 | `getent hosts B`；`hostname -f` | 正反解析一致 |
| 时间同步 | `chronyc tracking` | 偏移在毫秒级 |
| 迁移端口 | `ss -ltnp \| grep 4915`；`nc -zv B 49152` | 目标端监听，源端可连 |
| 防火墙 | `firewall-cmd --list-ports` / `iptables -L` | 49152–49215/tcp 放行 |

> `?port=55555` 是 **sshd 端口**，不是迁移端口。迁移端口由 `qemu.conf` 的 `migration_port_min/max` 决定，默认 49152–49215。

### 1.2 版本与机型兼容

| 检查项 | 命令 | 通过标准 |
|---|---|---|
| QEMU 版本 | `qemu-system-x86_64 --version`（两端） | 一致或在兼容矩阵内 |
| libvirt 版本 | `virsh version`（两端） | 一致或兼容 |
| machine type | `virsh dumpxml test2 \| grep '<type'`；`virsh -c '...' domcapabilities --machine pc-q35-7.2 --virttype kvm` | 两端一致，且目标端存在该 machine type |
| 固件 | `virsh dumpxml test2 \| grep -E 'loader\|nvram'`；`ls /usr/share/OVMF` | 固件版本/大小兼容 |

QEMU 官方文档明确：

> “migration is only supposed to work if you use the same machine type in both source and destination.”

固件方面：

> “Changes in firmware size can cause changes in the required RAMBlock size to hold the firmware and thus migration can fail.”

### 1.3 CPU / 拓扑 / 固件

| 检查项 | 命令 | 通过标准 |
|---|---|---|
| CPU 兼容 | 源端导出 `<cpu>`，在目标端执行 `virsh cpu-compare --xml cpu.xml` | 目标端支持源端 CPU 定义 |
| 主机 CPU 对比 | `virsh hypervisor-cpu-compare`（较新版本） | 返回兼容 |
| 拓扑 | `virsh dumpxml` 对比 sockets/cores/threads/dies | 完全一致 |
| CPU 特性策略 | 检查 `<feature policy='...'>` | 无 `require` 目标端缺失的特性 |
| TSC | 检查 `invtsc`、`tsc-frequency` | `invtsc` 不阻止迁移 |
| Hyper-V/KVM | 检查 `<hyperv>`、`<kvm>` | 一致 |

QEMU 官方文档：

> “we don't recommend to use -cpu host for migration.”

推荐 `mode='custom'` + `fallback='forbid'` + `check='full'`，并显式 `disable` 不可迁移特性。

### 1.4 内存与 NUMA

| 检查项 | 命令 | 通过标准 |
|---|---|---|
| 内存大小 | `virsh dominfo test2` | 目标端可分配 |
| 大页 | `grep -i huge /proc/meminfo`；`virsh capabilities` | 尺寸一致、数量足够 |
| NUMA | `virsh numatune test2`；`virsh capabilities` | 目标节点存在 |
| 内存热插拔 | 检查 `<maxMemory>`、slots | 目标端支持 |
| 气球 | `virsh dommemstat test2` | 无异常 |

### 1.5 存储（重点）

| 检查项 | 命令 | 通过标准 |
|---|---|---|
| 磁盘清单 | `virsh domblklist test2 --details` | 源/目标路径明确 |
| 镜像完整性 | `qemu-img check -f qcow2 /path/vda.qcow2` | 无错误/泄漏 |
| 镜像链 | `qemu-img info --backing-chain /path/vda.qcow2` | base 在两端一致（用 `-inc` 时） |
| 共享性 | `findmnt -T /path -o TARGET,FSTYPE,SOURCE`；`stat -f -c '%T' /path` | 非共享存储时用 `--copy-storage-all` |
| 目标空间 | `df -h /path` | ≥ 磁盘 virtual size |
| 目标镜像 | 检查目标路径是否存在、可写 | `--copy-storage-*` 要求镜像已存在 |
| 权限/标签 | `ls -lZ /path`；`getenforce` | qemu 用户可读写，SELinux 标签正确 |
| cache mode | `virsh dumpxml \| grep cache=` | `none` 或 `directsync`（否则不安全） |
| 快照 | `virsh snapshot-list test2` | 无阻碍迁移的外部快照 |
| 块作业 | `virsh blockjob test2 vda --info` | 无活动 mirror/commit |
| 加密盘 | `virsh secret-list` | 目标端 secret 可用 |
| NVRAM/TPM | `virsh dumpxml \| grep -E 'nvram\|tpm'` | 目标端文件/服务存在 |

libvirt 手册明确：磁盘未设 `cache='none'` 且不在集群文件系统上时，迁移被认为不安全，需要用 `--unsafe` 强制。

> `--copy-storage-all/inc` 只负责“把数据传到目标端同一位置的镜像”，**目标镜像必须事先存在**；路径不同要用 `--xml`。

### 1.6 网络

| 检查项 | 命令 | 通过标准 |
|---|---|---|
| 目标网桥/OVS | `ovs-vsctl show`；`brctl show`；`ip -br link` | 目标端存在同名网桥 |
| 端口组/VLAN | `virsh domiflist test2`；OVS 配置 | 目标端配置一致 |
| 迁移带宽 | `iperf3 -c B -t 10` | 满足内存+磁盘复制时间要求 |
| MTU | `ping -M do -s 1472 B` | 不丢包（按实际 MTU 调整） |
| MAC/IP | XML 中 `<mac address=...>` | 迁移后不变，无冲突 |
| 防火墙 | 迁移端口、NBD 端口 | 放行 |
| SR-IOV/直通网卡 | `lspci -nnk`；`virsh dumpxml` | 目标端 VF 可用 |

### 1.7 设备可迁移性

| 检查项 | 命令 | 通过标准 |
|---|---|---|
| 直通设备 | `virsh dumpxml \| grep -E '<hostdev\|<mdev'` | 设备/驱动支持 VFIO migration |
| GPU | `lspci -nnk` | 多数 GPU 不支持热迁移 |
| USB | `virsh dumpxml \| grep usb` | 重定向设备可重连 |
| virtiofs/9p | `virsh dumpxml \| grep -E 'filesystem\|virtiofs'` | 目标端共享路径存在 |
| TPM | `virsh dumpxml \| grep tpm` | 目标端 swtpm 可用 |
| 图形 | `virsh domdisplay test2` | SPICE/VNC 可重定位 |
| ROM 文件 | `virsh dumpxml \| grep '<rom'` | 目标端存在 |

### 1.8 安全

| 检查项 | 命令 | 通过标准 |
|---|---|---|
| SELinux/AppArmor | `getenforce`；`aa-status` | 标签/策略允许 |
| sVirt | `virsh dumpxml \| grep seclabel` | 目标端类别可用 |
| TLS 证书 | `openssl verify -CAfile ca-cert.pem server-cert.pem` | 证书链有效 |
| 主机名匹配 | `openssl x509 -checkhost nodeB -noout -in server-cert.pem` | SAN 包含 `--tls-destination` |
| 证书有效期 | `openssl x509 -dates -noout -in server-cert.pem` | 未过期 |
| 迁移加密 | `--tls` 或网络层隧道 | 数据面有加密 |

### 1.9 业务与性能

| 检查项 | 命令 | 通过标准 |
|---|---|---|
| 脏页率 | `virsh domstats --dirtyrate test2` | 带宽能覆盖脏页率 |
| vCPU/负载 | `virsh domstats --vcpu test2` | 无异常高负载 |
| 停机预算 | `virsh migrate-getmaxdowntime test2` | 与 SLA 匹配 |
| 并发迁移 | 端口范围/带宽 | 不超过容量 |
| 压缩/multifd | `--parallel`、`--comp-methods` | 按带宽/CPU 选择 |

### 1.10 迁移后验证预案（迁移前就要定好）

- 目标端 `virsh domstate` 为 running；
- 目标端 vCPU 时间持续增长、磁盘 I/O 有变化；
- Guest 内计数任务/心跳连续；
- IP/MAC 不变，ARP 收敛；
- 抽样或全量校验（SHA-256 / `qemu-img compare` / fsck）；
- 回滚方案：迁移失败时源端继续运行，目标端清理。

## 2. 影响因素矩阵

| 因素 | 类型 | 具体表现 | 缓解 |
|---|---|---|---|
| CPU 模型/特性不匹配 | 阻断 | `loadvm` 失败，源端回滚 | `cpu-compare`、custom 模型、禁用不可迁移特性 |
| machine type 不一致/目标缺失 | 阻断 | Prepare 失败或设备状态错乱 | 固定 machine type，目标端提供同型号 |
| QEMU/libvirt 版本跨度过大 | 阻断 | 设备状态/流格式不兼容 | 版本矩阵、同版本迁移 |
| 固件（OVMF）大小/版本变化 | 阻断 | RAMBlock 大小不一致，迁移失败 | 固定固件版本，pad 到 2 的幂 |
| 大页/NUMA 不足 | 阻断 | 目标端无法分配内存 | 预留大页、对齐 NUMA |
| cache mode 非 none | 一致性风险 | 非集群 FS 上可能数据损坏 | `cache=none` 或 `--unsafe`（自担风险） |
| 存储非共享且未复制 | 阻断 | 目标端磁盘空/旧 | `--copy-storage-all` + 预创建镜像 |
| 镜像链 base 不一致 | 阻断 | `-inc` 后 Guest 读错数据 | 同步 base，或改用 `-all` |
| 快照/块作业未清理 | 阻断 | mirror/commit 冲突 | 迁移前完成或取消 |
| 磁盘空间不足 | 阻断 | 建盘/写入失败 | 预留 ≥ virtual size |
| 迁移端口被防火墙拦截 | 阻断 | 连接超时 | 放行 49152–49215/tcp |
| DNS/主机名错误 | 阻断 | NBD/迁移 URI 连错 | 修正 hosts/DNS，或 `--migrateuri` |
| 带宽不足 | 收敛 | 迭代不收敛、超时 | 限速/压缩/multifd/专网 |
| 脏页率过高 | 收敛 | 停机超限 | auto-converge、dirty-limit、postcopy |
| `downtime-limit` 过小 | 收敛 | 反复迭代失败 | 放宽或换 postcopy |
| 直通设备不支持迁移 | 阻断 | 目标端设备状态缺失 | 迁移前拔除/改用 vGPU/厂商方案 |
| SEV/TDX 机密计算 | 阻断 | 内存加密状态不可迁移 | 冷迁移/重建 |
| SELinux/权限 | 阻断 | 目标端无法打开镜像 | 正确标签、qemu 用户权限 |
| TLS 证书/主机名不匹配 | 阻断 | TLS 握手失败 | `--tls-destination`、SAN 修正 |
| 并发迁移过多 | 性能 | 端口/带宽争抢 | 排队、限并发 |
| 时钟/TSC 差异 | 一致性 | Guest 时间跳变 | 固定 TSC、NTP |
| 网络配置不一致 | 一致性 | 迁移后失联 | 同名网桥/VLAN、ARP 收敛 |

## 3. 官方文档依据

1. **libvirt: Guest migration**
   <https://libvirt.org/migration.html>
   - 迁移流包含完整 Guest RAM，需保护；
   - 非共享存储迁移需预创建镜像，`--copy-storage-all/inc` 只传数据；
   - desturi/migrateuri 语义，`migration_host` 配置；
   - offline 迁移只迁定义。

2. **QEMU: Backwards compatibility**
   <https://www.qemu.org/docs/master/devel/migration/compatibility.html>
   - 必须使用相同 machine type；
   - CPU 特性取交集，管理程序负责配置；
   - 不推荐 `-cpu host` 做迁移。

3. **QEMU: Best practices**
   <https://www.qemu.org/docs/master/devel/migration/best-practices.html>
   - 固件随 RAM/ROM 迁移，大小变化会导致 RAMBlock 不匹配；
   - 建议按 machine type 固定固件版本。

4. **QEMU: Migration features**
   <https://www.qemu.org/docs/master/devel/migration/features.html>
   - postcopy、dirty limit、VFIO migration、multifd、压缩等能力。

5. **virsh migrate 手册**
   <https://manpages.debian.org/bookworm/libvirt-clients/virsh.1.en.html>
   - cache mode `none` / 集群 FS / `--unsafe`；
   - `--xml`、`--migrate-disks`、`--copy-storage-*` 行为；
   - `--tls`、`--tls-destination`、`--parallel`。

6. **libvirt domain XML**
   <https://libvirt.org/formatdomain.html>
   - CPU 模型/拓扑、磁盘 cache、memoryBacking、hostdev 等。

## 4. 预检脚本骨架

```bash
#!/usr/bin/env bash
# 用法: ./preflight.sh <domain> <dest-uri>
set -u
DOM=${1:?domain}
DEST=${2:?"qemu+ssh://root@B/system?port=55555"}
fail=0

ck() {
  local name=$1; shift
  printf '%-40s' "$name"
  if "$@" >/dev/null 2>&1; then echo OK; else echo FAIL; fail=1; fi
}

ck "libvirt 连接"        virsh -c "$DEST" version
ck "目标端域列表"        virsh -c "$DEST" list --all
ck "源端域状态"          virsh domstate "$DOM"
ck "磁盘清单"            virsh domblklist "$DOM" --details
ck "快照列表"            virsh snapshot-list "$DOM" --name
ck "无活动块作业"        bash -c "! virsh blockjob '$DOM' --all --info 2>/dev/null | grep -q ."
ck "CPU 兼容"            virsh cpu-compare --xml /tmp/source-cpu.xml
ck "目标 machine type"   virsh -c "$DEST" domcapabilities --virttype kvm
ck "磁盘镜像检查"        qemu-img check /var/lib/libvirt/images/"$DOM".qcow2
ck "存储文件系统"        findmnt -T /var/lib/libvirt/images
ck "SELinux"             getenforce
ck "时间同步"            chronyc tracking

echo
if [ "$fail" -eq 0 ]; then
  echo "预检通过，可进入迁移窗口"
else
  echo "存在未通过项，请先处理"
  exit 1
fi
```

> 脚本只是骨架，`--all`、`domcapabilities` 等参数需按你的 libvirt 版本调整。
