# 虚拟机热迁移功能原型 界面结构设计文档

> 日期：2026-11-05（2026-11-06 增补 R17 源端副本处置）
> 上游文档：《热迁移原型需求确认表_2026-11-05.md》（需求范围 R1–R17）、《热迁移操作剧本_2026-11-05.md》（场景A/A2/B/C/D）
> 本文档性质：界面原型设计（wireframe 层），**不涉及任何后端实现**；界面风格对齐现有 kvm_web 管理台（Element UI）
> 编号规则：区块编号 B1–B5，区块内控件编号 c0、c2…（保留原编号，c1 为已删除的 VSM 选择控件，不重排以免与剧本步骤失联），按钮编号 btn-0…

## 1. 功能入口与总体结构

### 1.1 入口设计（对齐平台现有交互范式）

**不新建独立页面。** 热迁移功能完全沿用平台既有范式：在 VSM 列表（vm-manage）**右键菜单**中加入「热迁移」项，点击后弹出热迁移操作弹窗——与现有「网络配置」「管理快照」同一交互路径（右键选定 → 弹窗配置）。

右键菜单项设计（插入 `ctxMenuItems`，位于「克隆」之后、「强制重置」之前，与其余操作项平级不加分隔线）：

| 属性 | 值 |
|---|---|
| cmd | `migrate` |
| label | 热迁移 |
| icon | Position（Element Plus 图标，迁移语义） |
| disabled 判定 | 无禁用态：运行中 → 默认热迁移；已关机 → 默认冷迁移（两种状态都可迁移）；锁定行与其他操作一致按锁定规则处理 |

### 1.2 弹窗结构

右键已选定 VSM，因此不需要"选择 VSM"控件；弹窗尺寸有限，区块重新分配为"**一主弹窗 + 一进度弹窗**"两级：

```
右键「热迁移」
   │
   ▼
【热迁移弹窗】（主操作界面，Dialog，宽约 640px，对齐网络配置弹窗规格）
 ├─ 顶部：VSM 信息条（名称/状态/当前节点，只读——来自右键所在行，不可改选）
 ├─ B1 参数区（意图/目标节点+系统推荐/存储池/模式/限速，见 §2）
 ├─ B2 推荐结果区（候选节点卡片，选定后才加载存储池，见 §3）
 ├─ B3 预检报告区（对已选定节点深度校验，见 §4）
 └─ 底部按钮：【系统推荐】【预检】【提交迁移】【取消】
   │ 提交并二次确认后
   ▼
【迁移进度弹窗】（独立 Dialog，替换主弹窗，见 §5）
 ├─ B4 进度视图（阶段指示器/实时数据/风险告警/取消按钮）
 └─ B5 结果验证卡（完成后在进度弹窗内呈现）
   │
   ▼
迁移留痕 → 日志中心→操作日志（模块=跨节点迁移，弹窗不留历史，见 §7）
```

各区块状态互斥关系：B2 在点击【系统推荐】后出现；B2 选定节点后 B1 的存储池才有选项；换节点/换意图后 B3 失效需重检；提交后主弹窗关闭、进度弹窗出现；B5 仅出现在进度弹窗的完成态内。**B2 与 B3 的先后不可颠倒**：推荐解决"迁到哪台机器"，预检解决"这台机器上的这块盘能不能安放、网络能不能落位"。

原「跨节点迁移」独立页面保留其中"主机节点"Tab（节点管理是管理员维护性功能，不适合塞进右键弹窗）；其"VM迁移"Tab 由右键入口取代，逐步废弃。

## 2. B1 发起区（覆盖 R1 / R3 / R4 / R5 / R8）

> **前提事实（本项目为非共享存储迁移）**：磁盘须整盘复制到目标节点，因此目标存储池为主表单必填项；网桥、VLAN、端口转发均为**节点本地资源**，迁移后须自动重新落位，不向用户暴露交换机/安全组选择控件。

> **流程前提（推荐必须先于存储池）**：存储池选项按目标节点加载（后端 `GET /api/storage-pool/vm-targets` 需指定节点）。因此**不能等预检再给推荐**——否则用户在选存储池时目标节点还是悬空的。正确顺序是：意图 → 【系统推荐】得出候选节点 → 用户选定节点 → 加载该节点的存储池 → 选池 → 预检。这是本版把"推荐"从预检中拆出来的原因。

> **空态引导（C2）**：未点【系统推荐】且未选节点时，B1 下方灰字"选择目标节点，或点【系统推荐】由系统给出候选"；已选节点未选池时，灰字"选定目标存储池后即可预检"。两句话替代用户对流程的记忆。

### 2.1 控件清单

| 编号 | 控件 | 类型 | 取值与默认 | 交互规则 | 需求 |
|---|---|---|---|---|---|
| c0 | VSM 信息条 | 只读展示条 | 右键所在行的 VSM | 名称/运行状态/当前节点/规格/IP/磁盘总量 一行展示，不可改选——**右键入口天然消除了选错 VSM 的可能** | C1 |
| c2 | 迁移意图 | 单选组 | 默认"未选择"；可选项：未选择/负载均衡/设备升级维护/资源集中/故障规避/安全合规隔离/网络位置优化 | 选定后显示该意图推荐侧重的一句话说明；**保持"未选择"可直接手选目标节点，无任何阻塞**（兜底路径，场景C）；切换意图会让已有候选结果失效 | R3 |
| c3 | 目标节点 | 下拉 + 【系统推荐】按钮 | 默认**空**（不预填，避免"看起来已选好"）；其余项为全部在线节点（源节点置灰） | 点【系统推荐】后给出 2–3 个候选（见 B2），**自动回填排序第一的候选**（用户已显式点了按钮，回填不构成"擅自替用户决定"），用户可在卡片上改选其他候选；也可完全绕过推荐直接手选；**手选节点时存储池仍按该节点加载，预检仍执行完整硬过滤** | R3 |
| c4 | 迁移模式 | 单选组 | VSM 运行中默认"热迁移"，关机态锁定"冷迁移"（置灰+提示）；运行中改选"冷迁移"时弹中断提示二次确认 | 默认值随右键行状态自动确定 | R4 |
| c5 | 带宽限速 | 开关+数值框（MiB/s，1–2000） | 默认关 | 开启后数值框出现，默认 500；预检报告体现占用预估 | R5 |
| c6 | **目标存储池** | 下拉（必填） | 无默认；**选项仅在该节点的存储池查询完成后才填充**，未选节点时禁用并提示"请先选定目标节点" | 未选择时【预检】【提交迁移】均不可用；选项旁展示各池可用容量；换节点后若原池不属于新节点则自动清空 | R8 |
| c7 | 高级项折叠区 | 折叠面板 | 默认收起 | 仅收纳 **CPU 节流**（开关+百分比），保持主表单简洁 | — |

> **设计说明**：目标交换机 / 目标安全组**不作为用户控件存在**。它们是节点本地资源，由后端按"同名 + 同 CIDR"（交换机）与"同名"（安全组）自动匹配——推荐阶段用它判定候选是否合格（不匹配的节点不进候选，理由写入推荐失败面板），预检阶段对已选节点复核并作为 B3 的检查项展示（见 b3-b）。匹配失败即阻断迁移，提示属于目标节点资源缺失，交由管理员在节点侧补齐后重试——而不是让用户在迁移弹窗里手工挑一个勉强的替代品（那会导致迁移成功但业务网络语义改变）。

## 3. B2 推荐结果区（覆盖 R3 / R3a / R8）

点击【系统推荐】后在 B1 参数区下方展开，**位于预检之前**。形式为候选节点卡片列表（纵向堆叠，非横向平铺——卡片内含多行信息，横向排两列会在 640px 弹窗内挤成多行）。

### 3.1 区块抬头

`系统推荐 2 个候选节点（已通过硬过滤，按「设备升级维护」意图排序）`

- 数字为实际候选数（2–3 个，后端有多合格节点时取前 3）；
- 意图为"未选择"时改为"按综合可用性排序"；
- 候选卡片数量与抬头数字必须一致，缺一即为缺陷。

### 3.2 候选节点卡片（每个候选一张，可点击切换选中）

| 编号 | 行 | 内容 |
|---|---|---|
| b2-a | 首行 | 节点名称（主字号）+ `推荐首选` 绿色标签（仅排第一的候选有此标签）+ 右侧该节点的可用存储池徽章（见 b2-b） |
| b2-b | 存储池徽章行 | 该节点可用的存储池徽章，格式 `pool-ssd 180 GiB`，逐池一个小标签——**这是"先选节点才能选池"的可视化依据：池跟着节点走** |
| b2-c | 资源 | `资源　CPU 余量 45% / 内存余量 32 GiB` |
| b2-d | 网络落位 | `网络落位　已匹配交换机 sw-caiwu（10.0.1.0/24）+ 安全组 sg-caiwu`；未匹配时此行变红，该候选本不应出现（已被硬过滤），出现即视为后端缺陷 |
| b2-e | 意图理由 | 意图标签 + 一句话排序理由，如 `设备升级维护　承接后整体负载预计 62%，在安全线内` |
| b2-f | 操作 | 卡片底部右对齐按钮：未选中为【选此节点】（描边主色），已选中为【已选定】（描边绿色，按钮置灰不可重复点） |

- 选中态（`.is-picked`）用主题色边框 + 浅色底，与未选中卡片明确区分；该卡的按钮同时由【选此节点】变为【已选定】（绿色）；
- 点【选此节点】＝回填 c3 目标节点 + 触发该节点存储池加载（实现见演示页）；**候选列表不自动收起**——卡片本身即"可选项的比较表"，收起后用户就看不出"还有别的候选"，改选又要点一次推荐；若用户此前已选过存储池，回填节点后因池属于旧节点而清空，需重新选池——此清空是刻意的，不能保留错节点的池；
- 换意图后已有候选即失效（旧候选是按旧意图排的序），列表清空，需重新点【系统推荐】。

### 3.3 推荐失败面板

硬过滤后候选为空时，在同一位置以红色面板替代候选列表：

| 元素 | 内容 |
|---|---|
| 标题 | `无可用目标节点` |
| 逐节点淘汰原因 | 每个被淘汰节点一行，格式 `· node-02：目标节点不存在同名交换机 sw-caiwu（10.0.1.0/24）`；`· node-03：目标存储池 pool-ssd 可用空间不足（需 60 GiB，可用 20 GiB）`；`· node-04：CPU 型号不兼容（AMD EPYC 9654 vs Intel Xeon 6338）` |
| 建议动作 | 按原因归类给出可执行建议："① 在 node-02 创建同名交换机与安全组后重试；② 或清理 node-03 存储池空间" |
| 后续状态 | 【预检】【提交迁移】保持不可用；用户可改用场景C 手选节点（手选仍会走完整硬过滤） |

> **此面板的位置是本版设计的关键修正**：推荐失败必须发生在**选节点阶段**。若把失败面板放在预检之后，用户已经在"推荐给出的节点"上选过存储池，才发现节点根本不可用，交互上是倒序的。

## 4. B3 预检报告区（覆盖 R1 / R3a / R5 / R8）

预检完成后出现在 B2 下方，卡片式，两段结构。**预检不再产出推荐**——推荐已在 B2 完成，此处只对"用户已选定的节点 + 存储池"做深度校验。

| 编号 | 子区块 | 内容与状态 | 需求 |
|---|---|---|---|
| b3-a | 检查结论横幅 | 绿色"预检通过，可以迁移" / 黄色"预检通过，存在 N 项警告" / 红色"存在阻断项，不可迁移"（此时 btn-2 置灰） | R1 |
| b3-b | 明细列表 | 通过项（绿勾）/ 警告项（黄叹号，附建议动作）/ 阻断项（红叉，附原因）。检查维度固定六类：<br>① 兼容性（CPU / 机器类型）<br>② 资源（CPU / 内存）<br>③ **磁盘容量核算**（磁盘总量 vs 目标池可用空间，见 R8）<br>④ **网络落位**（同 CIDR 交换机匹配 + 同名安全组匹配，见 R3a）<br>⑤ 磁盘路径冲突检查<br>⑥ 带宽预估（热迁移时） | R1/R3a/R5/R8 |
| b3-c | 落位提示 | 灰字一行："预检针对**已选定的目标节点与存储池**执行深度校验；如需换节点请回到上方重新推荐或手选。"——明确预检的校验对象，避免用户误以为预检还管选节点 | C2 |

> **手选节点的处理**：场景C 直接手选节点、不点【系统推荐】时，B2 不出现，B3 的六类检查**一项不减**。推荐只是"帮用户挑候选"，不是"代替预检做硬过滤"——手选路径下硬过滤的结论全部由 B3 承载。

> **预检不通过（接口报错）** 与 **预检阻断（检查项不通过）** 是两回事：前者红条 + 可重试，后者渲染 b3-b 的红色明细并锁死 btn-2。

## 5. B4 进度视图（覆盖 R9 / R10 / R11）

提交迁移后以弹窗形式出现（对齐现有页面进度弹窗，但升级为全信息视图），迁移全程不可关闭（防误操作，C1）。

### 5.1 阶段指示器（R9）

横向步骤条，五站：

```
● 预检完成 ── ● 数据同步中 ── ● 准备切换 ── ● 切换完成 ── ● 迁移成功
```

- 当前站高亮+呼吸动画，已过站点绿勾，未到站点灰；
- 每站下方一行小字说明当前站在做什么（C3 概念屏蔽）：
  - 数据同步中："正在把 VSM 的内存与磁盘数据同步到目标节点，VSM 业务不受影响"
  - 准备切换："即将进行源到目标切换，存在毫秒级业务瞬断，请勿在此期间操作该 VSM"

### 5.2 实时数据条（R9）

进度百分比 + 三项实时数值：已同步/剩余数据量、当前速率、预计剩余时间。

### 5.3 风险告警条（R10）

触发条件（任一）：脏页率过高导致进度反复 / 预计剩余时间持续增长。出现时为页面顶部黄色横幅，**内置建议动作按钮**：

- 【启用 CPU 节流】（一键采纳，按钮执行后变"已启用 50%"）
- 【降低限速】（仅 c5 开启时出现）
- 文案预留"降级为冷迁移"（本次范围外，置灰）

### 5.4 取消按钮（R11）

| 编号 | 按钮 | 行为 |
|---|---|---|
| btn-4 | 取消迁移 | 弹二次确认："取消后 VSM 将继续运行在源节点 {node}。**目标节点上已复制的临时磁盘数据将被清理**。确认取消？"确认后按钮变"正在安全取消…"，阶段指示器追加"取消中"状态；完成显示绿色提示"取消完成，VSM 运行状态正常，仍位于源节点 {node}；目标端临时磁盘数据已清理"，进度视图变为可关闭 | R11 |

> **非共享存储的取消语义**：与共享存储不同，本场景下目标节点已写入部分磁盘文件，取消必须清理，否则下次迁移会因"目标磁盘已存在"被预检阻断（对应后端检查 `目标磁盘已存在: {path}`）。取消完成提示中须明确告知用户清理已发生，避免其误以为目标端留有半成品。

禁用规则：**"准备切换"站及之后取消按钮置灰**（对应源码：切换阶段取消属危险操作，不提供入口），置灰时 hover 提示"切换阶段不可取消"。

### 6.2 源端副本处置的三条硬约束（设计说明）

**约束一：源端的三样东西里，只有磁盘文件是可选的。**

| 源端的什么 | 处置 | 可选项？ |
|---|---|---|
| 虚拟机定义 / 运行状态 | 立即注销 | **否** |
| 端口转发、网桥等节点本地落位 | 立即释放 | **否** |
| **磁盘文件** | 按 b5-f1/f2/f3 三档 | **是** |

前两项若保留，源端仍占着 vCPU、内存、端口转发和同名记录，会直接导致目标端重名冲突。**它们没有"保留"这个选项，不得与磁盘文件混为一谈。**

**约束二：保留期只在"结论不明确"时存在，不是回滚保险。**

源端副本的唯一用途是"目标端磁盘损坏、整个重来"这一灾难场景——**不是日常回滚**。日常回滚靠反向再迁一次（耗时等于正向迁移），不需要源盘。因此：

- 全绿即清（保留期 0），不留观察窗口——**"再观察一阵"的价值低于"少挂一份密钥材料"的合规价值**；
- 只有黄项才进保留期，因为此时"迁移是否真的成功"尚无定论；
- 保留期**硬上限 72h，不可设为无限**，防止出现"某些 VSM 的源盘悄悄留了半年"。

**约束三：弹窗关闭后入口不能丢。**

b5-f2 的【立即清除源端副本】只存在于进度弹窗内，而进度弹窗在完成后即可关闭。若管理员手快关掉，入口就消失了。因此**列表页必须有常驻入口**（见 §6.3）。

### 6.4 清除动作的确认文案（不可用中性词）

| 场景 | 按钮 | 二次确认文案 |
|---|---|---|
| b5-f2 进度弹窗内 | 【立即清除源端副本】 | `清除后无法再从源节点 {node} 恢复此 VSM。`<br>`{node} 上的磁盘文件 {path}（{size} GiB）将被永久删除。`<br>`确认清除？`　→【取消】【**确认清除**】（红） |

### 6.6 三条必须做的核实（否则本节是空话）

1. **不能信命令返回码**：清除后须 `ls` 源端磁盘目录确认文件真的消失（不是 0 字节占位、不是目录残留）。与 RQ-5-06 目标端清理是同一类要求。
2. **清除失败路径必须存在**：文件被进程占用、权限不对、目录只读都会让删除失败。失败须红色告警 + 转人工，**绝不能静默吞掉**——留一份密钥材料无人知晓，比明确留着更糟。
3. **后端现状未核实**：`virsh migrate` 成功后源端磁盘是否已被自动删除、由哪一行执行、是否校验结果——**这是 R17 落地的前提，需先查代码**（见需求确认表 §6 待确认问题第 1 条）。

## 7. 迁移历史的承载方式（覆盖 R16，**不在本页面呈现列表**）

## 9. 状态与文案原则（贯穿全页）

1. **危险操作必二次确认**：提交迁移、取消迁移、运行中改选冷迁移——三者均弹确认，且确认文案写明后果（C1）；
2. **跳过预检必须显式且刺眼**：红色警示图标+hover 风险提示，不用普通开关样式（C1，对齐 PVE `--force` 仅 root 的处理）；
3. **一切业务影响用业务语言**：不出现"脏页率""收敛""网桥"字样于主文案，只出现在括号内的技术注释（C3）；
4. **进度视图不可误关**：迁移中弹窗无关闭按钮，仅完成/取消完成后可关闭（C1）；
5. **空态引导**：未点【系统推荐】且未选节点时，B1 下方灰字"选择目标节点，或点【系统推荐】由系统给出候选"；已选节点未选池时，灰字"选定目标存储池后即可预检"（C2）；
6. **网络落位不可交给用户决策**：交换机/安全组不设用户控件，仅展示系统匹配结果（R3a）。匹配失败属目标节点资源缺失，应提示补齐节点侧资源后重试，不提供"凑合选一个"的通路——否则迁移"成功"但业务网络语义已改变；
7. **推荐只是"给出候选"，不是"代替选择"**：候选卡片必须可切换、可放弃并手动指定节点；推荐失败时界面不能把人堵死，手选通路始终敞开（R3 的兜底语义）；
8. **顺序不可倒置**：选节点 → 选池 → 预检。任何"先选池再知道节点"或"预检完才告诉用户节点根本不可用"的界面都算设计缺陷。
9. **不可逆动作不用中性词**（R17）：源端副本的销毁统一称"**清除**"，确认文案必须写明"无法再恢复"与具体文件路径、容量。不使用"删除""清理""释放"这类听上去可逆或无害的表达。
10. **入口跟着数据状态走，不跟着弹窗生命周期走**（R17）：源端副本保留期可能长达 24h，而进度弹窗在完成后即关闭。任何"只在某个弹窗里存在"的长期状态入口都应视为设计缺陷——必须在列表页有常驻表达（角标 + 右键项）。
11. **"不适用"与"无需处理"要区分**（R17）：迁移失败/取消时不存在源端副本这个概念，B5 卡**不出现**「源端处置」行，而不是显示"无需处理"——后者会让用户误以为系统做过判断。
