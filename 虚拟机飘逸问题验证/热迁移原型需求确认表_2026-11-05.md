# 虚拟机热迁移功能原型 需求确认表

> 日期：2026-11-05
> 编制依据：项目内部术语约定（虚拟机对外统称 VSM）、现有接口文档《虚拟机生命周期管理接口清单》（§5 跨节点迁移）、现有页面 vm-migration.vue、Proxmox VE / OpenStack Horizon 迁移界面调研
> 文档性质：原型设计范围锁定文档，需导师/项目组确认后方可进入原型设计阶段

## 1. 背景与目标

轻量化云密码底座（KVM 后端 + Web 管理台）已具备 VSM 生命周期管理能力，跨节点迁移后端接口已存在（`GET /migration/options`、`POST /migration/preview`、`POST /migration/migrate`、`POST /migration/adopt`、`GET /host/list`），但管理台迁移界面功能尚不完整。

本阶段目标：**完成热迁移功能的界面原型设计**（页面结构、按钮、操作流程、状态与反馈），能够演示基本功能。**不涉及任何后端实现。**

## 2. 目标受众

| 受众 | 场景 | 界面关注点 |
|---|---|---|
| 云平台管理员（主要） | 节点维护/升级、资源均衡时迁移 VSM | 操作安全、进度可视、可取消 |
| 密码服务运维/安全人员 | 升级窗口期不停机换宿主机 | 业务中断影响、迁移结果可信 |
| 上层平台/集成方（API 调用方） | 自动化编排迁移 | 不直接使用界面，仅要求接口规范 |

由此确立的三条设计约束（后续所有界面决策依据）：

- **C1 谨慎优先**：VSM 是密码服务载体，中断即业务事故，宁可多一步确认，不可少一步拦截；
- **C2 低频使用**：管理员可能月级使用一次，界面须自带解释文案，不依赖用户记忆；
- **C3 概念屏蔽**：脏页率、收敛、块迁移等源码层概念须翻译为"预计中断时长""风险提示"等业务语言。

### 迁移意图定义与推荐逻辑（R3 的设计依据）

推荐为**两段式**：先做与意图无关的硬过滤（不合格节点直接出局），再按意图对剩余候选软排序。这样意图只负责"在合格候选里排第一"，**不能放宽任何一项硬性条件**。

**推荐发生的时机（R3 的流程约束）**：推荐由独立的【系统推荐】按钮触发，位于**预检之前**。理由是目标存储池的选项按节点加载（后端 `/api/storage-pool/vm-targets` 需指定节点），若推荐放在预检结果里，用户在选存储池时目标节点还是悬空的。因此顺序固定为：

```
声明意图 →【系统推荐】→ 候选节点卡片（2–3 个）→ 用户选定节点 → 加载该节点存储池 → 选池 → 预检 → 提交
```

推荐产出**多个候选**而非单一结论，是刻意的：硬过滤只能排除"不可行"，其内部往往仍有多个同等合格的节点，谁排第一取决于意图偏好，属于可解释的排序而非客观最优。只给一个答案等于把排序偏好伪装成唯一解。候选卡支持切换选中，且**不点推荐直接手选节点始终可用**（兜底路径，见操作剧本场景C）。

**推荐不改动硬过滤的结论**：手选节点后预检仍执行完整六类检查，不走捷径；推荐失败时手选通路也不被封死，但预检会给出同样的阻断结论。

**第 1 段 · 硬过滤（任一不满足即淘汰该节点）**

| 过滤项 | 判定依据 | 失败后果 |
|---|---|---|
| CPU / 机器类型兼容 | CPU 型号或微架构兼容、machine type 一致 | 无法热迁移 |
| 资源充足 | 目标节点剩余 CPU/内存满足 VSM 规格 | 无法承接 |
| 存储容量 | 目标存储池可用空间 ≥ 磁盘总量（非共享存储须整盘复制） | 复制中途失败 |
| 网络落位 | 目标节点存在同名同 CIDR 的 VPC 交换机，且存在同名安全组 | 迁移后业务网络不通 |
| 磁盘路径无冲突 | 目标路径未被占用 | 预检阻断 |

硬过滤后候选为空 → **推荐失败面板**（出现在选节点阶段，而非预检之后），逐节点列出不满足原因（如"node-02：目标节点不存在同名交换机 sw-caiwu（10.0.1.0/24）"），而非笼统报错。

**第 2 段 · 意图软排序（在合格候选中决定谁排第一、谁排第二…）**

| 意图 | 场景说明 | 推荐侧重 |
|---|---|---|
| 负载均衡 | 源节点 CPU/内存过高，迁移分担 | 资源余量最大的节点 |
| 设备升级维护 | 源节点计划升级/维护，需清空 VSM | 排除源节点，选承接后整体负载仍安全的节点 |
| 资源集中 | 集群负载低，VSM 聚拢以空出节点关机省电 | 迁移后可关闭最多节点的聚拢方案 |
| 故障规避 | 源节点出现硬件告警（风扇/内存 ECC/磁盘预测故障） | 健康度最高（硬过滤项不可放宽） |
| 安全合规隔离 | 高敏感 VSM 需物理隔离，迁往专用机 | 限定带"专机/专池"标签的节点 |
| 网络位置优化 | 业务方网络位置变化，就近降时延 | 按网络时延/拓扑就近选择 |

> 候选卡中应写明该候选的网络落位结果（如"已匹配交换机 sw-caiwu（10.0.1.0/24）、安全组 sg-caiwu"），让管理员不必理解网桥概念也能确认网络不会断。未声明意图时，候选按综合可用性排序，抬头文案改为"按综合可用性排序"。

## 4. 范围外说明（明确不做，防止范围蔓延）

以下内容本次原型**不包含**，如需后续支持另行立项：

- 后端任何功能实现/接口开发（本次仅界面原型）；
- **共享存储迁移**：后端迁移命令始终携带 `--copy-storage-inc`（整盘复制），不存在"源目标共享同一份磁盘"的代码路径；且迁移所用的存储池模型（v1 `host_storage_pools`，按 `lsblk` 块设备登记）不含 `kind` 字段，NFS 等共享挂载点在其中不可见。因此本次原型**一律按非共享存储设计**（目标存储池必填、磁盘容量核算、磁盘落位核对、取消时清理目标端残留），不做"检测到共享存储则简化流程"的分支；共享存储若后续支持，需要先在后端补齐存储类型判定与对应的迁移路径；
- TLS/国密证书配置界面（迁移通道加密状态仅作展示，不提供证书管理）；
- 批量迁移、定时迁移、迁移编排；
- 迁移失败自动重试与断点恢复（源码分析文档第十一章中属产品化远期项）；
- post-copy（后拷贝）模式切换界面；
- **源端副本保留期的自定义配置界面**：R17 的三档策略中，保留期默认 24h、硬上限 72h，均为平台级配置，**本次原型不提供管理员在界面上调这个数值的入口**（仅展示倒计时）。理由：该值属安全策略参数，应由部署规范确定，不宜由单次迁移的操作者临时放宽。

## 6. 待确认问题（R17 引入，需在原型评审前定）

1. **后端现状未核实**：迁移成功后 `virsh migrate` 是否已删除源端磁盘、由哪一行代码执行、是否校验删除结果——**这是 R17 能否落地的前提，需先查代码**。若现状为"已自动删除"，则 R17 的①档为既成事实、只需补②档保留期；若现状为"不删除"，则①档需新增实现。
2. **保留期中源盘是否需要标记为"待删"**：若管理员在保留期内手工对源盘做了操作（挂载、复制、快照），系统能否察觉？建议至少在清除前做一次归属校验，避免误删管理员另行创建的副本。
3. **清除动作的角色权限**：本文档假定【立即清除源端副本】仅平台管理员可见。但平台目前无角色分级（连接方式为 `qemu+ssh://root`，见 Hyper-V 记录 §2.1），**若要区分权限，须先有权限模型**——本原型不承载，列为依赖项。
4. **保留期到期时 VSM 已再次迁移怎么办**：A→B 迁移留下保留期源盘，保留期内又从 B 迁到 C，此时 A 端那份副本的到期计时是否延续、清除动作是否仍指向 A 端。建议：以"副本 ID"为清除对象，而非"VSM ID"，避免清除错节点。
