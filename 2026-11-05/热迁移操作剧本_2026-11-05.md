# 虚拟机热迁移功能原型 管理员操作剧本

> 日期：2026-11-05
> 上游文档：《热迁移原型需求确认表_2026-11-05.md》（需求编号 R1–R16 以其为准）
> 用途：驱动界面结构设计（每个剧本步骤 ↔ 界面区块/按钮），并作为原型演示脚本的基础
> 写法说明：剧本以"管理员动作 → 界面响应"成对书写，括号内标注对应需求编号
> **流程主线（本版关键）**：意图 →【系统推荐】得出 2–3 个候选节点 → 选定节点 → 加载该节点存储池 → 选池 → 预检 → 提交。推荐必须先于存储池，因为存储池选项是按目标节点加载的。

## 场景A：意图驱动的标准热迁移（主力演示线）

**背景设定**：管理员计划对源节点 node-01 进行设备升级维护，需将其上承载财务密码服务的 VSM（vsm-caiwu-01，运行中，磁盘总量 60 GiB）迁走，业务不能中断。**本项目为非共享存储迁移，磁盘需整盘复制到目标节点。**

| 步骤 | 管理员动作 | 界面响应 |
|---|---|---|
| A1 | 打开虚拟机列表页（vm-manage） | 加载 VSM 列表（GET /vsm/list） |
| A2 | 在 vsm-caiwu-01 行上**右键**，选择「热迁移」 | 弹出热迁移主弹窗；顶部信息条展示该 VSM：运行中 / 所在节点 node-01 / 规格 4C8G / 磁盘总量 60 GiB（VSM 已由右键选定，无需再选择） |
| A3 | **声明迁移意图：设备升级维护**（单选，选"设备升级维护"） | 意图选中后界面提示该意图的推荐侧重："将排除源节点，推荐承接后整体负载仍安全的节点"（R3） |
| A4 | 点击【系统推荐】 | 按钮进入加载态"推荐中…"；下方展开**推荐结果区**，抬头显示"系统推荐 2 个候选节点（已通过硬过滤，按「设备升级维护」意图排序）"（R3） |
| A5 | 查看候选节点卡片 | 两张卡片，每张含：节点名 +（首选卡）绿色 `推荐首选` 标签 / 可用存储池徽章（如 `pool-ssd 180 GiB`）/ 资源余量 / 网络落位匹配结果 / 意图排序理由（R3/R3a/R8）。卡片纵向堆叠，可点击切换选中 |
| A6 | 在 node-02 卡片上点【选此节点】（该卡亦已因是首选被自动回填） | 目标节点回填 node-02，该卡片变选中态、按钮变【已选定】（绿色）；其余候选卡仍在，可随时改选；**存储池下拉此时才加载 node-02 的池选项**（R8） |
| A7 | 选择**目标存储池**：pool-ssd（可用 180 GiB） | 存储池选项旁显示各池可用容量；未选时【预检】【提交迁移】均不可用（R8） |
| A8 | 点击【预检】 | 按钮进入加载态"预检中…"；弹窗内展开预检进行中提示 |
| A9 | 等待预检完成 | 展示预检报告（R1），六类检查全部列出：<br>① 兼容性——CPU 同型号、机器类型一致 ✓<br>② 资源——目标节点余量满足 4C8G ✓<br>③ **磁盘容量核算**——磁盘总量 60 GiB / pool-ssd 可用 180 GiB ✓（R8）<br>④ **网络落位**——已匹配交换机 sw-caiwu（10.0.1.0/24）、安全组 sg-caiwu ✓（R3a）<br>⑤ 磁盘路径无冲突 ✓<br>⑥ 带宽预估——⚠ 警告（见 A10） |
| A10 | 查看报告中的警告项 | 警告项（黄色）："迁移预计传输 60 GiB 磁盘 + 4 GiB 内存，按当前默认带宽约占业务网络 15%，预计耗时 8 分钟"（R5 前置） |
| A11 | 响应警告：开启带宽限速，设 500 MiB/s | 限速开关展开数值框，输入后界面回显预估占用（R5） |
| A12 | 确认迁移模式 | 模式单选默认"热迁移"；允许改选"冷迁移"，改选时弹提示"冷迁移将先关机，业务会中断"，需二次确认（R4） |
| A13 | 点击【提交迁移】 | 弹出二次确认框：摘要展示 VSM / 意图 / 目标节点 node-02（系统推荐）/ 模式热迁移 / 限速 500MiB/s / **目标存储池 pool-ssd（可用 180 GiB）** / **网络落位（交换机 sw-caiwu + 安全组 sg-caiwu）**；并显示"将复制磁盘 60 GiB 至目标节点，预计约 8 分钟"（非共享存储必显）；确认按钮"确认开始迁移" |
| A14 | 点击确认 | 主弹窗关闭，弹出**迁移进度弹窗**（R9），阶段指示器亮起第一站"预检完成 → 数据同步中"；进度条推进，显示实时速率 |
| A15 | 观察数据同步阶段 | 界面展示：已复制数据量（磁盘 + 内存）/ 剩余量 / 当前速率 / 预计剩余时间（R9） |
| A16 | （演示条件触发）收敛变慢告警 | 黄色风险告警条（R10）："该 VSM 磁盘写入与内存写入都较频繁，复制收敛变慢。建议：① 启用 CPU 节流；② 降低限速让业务优先" |
| A17 | 采纳建议：点击告警条上的【启用节流】 | 告警条收起，参数区显示"CPU 节流 50% 已启用"，进度推进速度恢复（R10） |
| A18 | 观察阶段推进到"准备切换" | 蓝色横幅："即将进行源到目标切换，存在毫秒级业务瞬断，请勿在此期间对该 VSM 发起操作"（R9） |
| A19 | 等待切换 | 阶段指示器亮起"切换完成"，进度条 100% |
| A20 | 查看**结果验证卡片**（R14） | 五项验证全绿：运行状态=运行中 / IP=192.168.10.25（与迁移前一致）/ 服务探活=通过 / **磁盘落位=pool-ssd:/var/lib/libvirt/images/vsm-caiwu-01.qcow2（容量 60 GiB 核对一致）** / **对外端口=端口转发已重建，端口号未变（8443）**；下方按钮【关闭】【查看操作日志】 |
| A21 | 点击【查看操作日志】 | 跳转日志中心→操作日志，预置筛选模块=跨节点迁移，可见记录链：迁移预检（通过）/ 提交迁移（原因含"意图=设备升级维护、热迁移、限速500MiB/s"/ 迁移完成（成功，时长由首末记录时间差可见）（R16） |

## 场景B：迁移中安全取消（异常处置演示线）

**背景设定**：管理员发起一次负载均衡迁移，数据同步阶段发现目标节点磁盘空间告警，决定中止。

| 步骤 | 管理员动作 | 界面响应 |
|---|---|---|
| B1–B9 | 同场景A A1–A9，但意图选"负载均衡"；点【系统推荐】后候选首选为 node-03，在 node-03 卡片上点【选择此节点】，选其存储池 pool-ssd，再点【预检】 | 预检通过；因意图=负载均衡，卡片排序理由是"node-03 资源余量最大：CPU 余量 45%、内存余量 32 GiB" |
| B10 | 提交并确认 | 主弹窗关闭、进度弹窗出现，数据同步中 |
| B11 | 收到目标节点磁盘告警（运维群消息，界面外事件） | —— |
| B12 | 点击进度弹窗中的【取消迁移】 | 弹出二次确认："取消后 VSM 将继续运行在源节点 node-01。**目标节点上已复制的临时磁盘数据将被清理**。确认取消？"（R11） |
| B13 | 点击确认 | 按钮变为"正在安全取消…"，阶段指示器追加"取消中"状态 |
| B14 | 等待取消完成 | 界面提示（绿色）："取消完成，VSM vsm-x 运行状态正常，仍位于 node-01；目标端临时磁盘数据已清理"，进度弹窗变为可关闭（R11） |
| B15 | 到日志中心→操作日志查看本次记录 | 模块=跨节点迁移下新增记录：取消迁移，结果=成功（非失败），原因="操作者主动取消，临时磁盘已清理"（R16） |

**剧本设计意图**：取消演示必须传达两点——①取消是安全操作、VSM 留在源端（对应源码里迁移期间源端 domain 从未销毁，Confirm 失败才回滚）；②**非共享存储下取消必须清理目标端残留磁盘**，否则下次迁移会被"目标磁盘已存在"阻断。

## 场景C：无意图手选（兜底路径演示线，最短）

**背景设定**：管理员明确知道要迁往 node-04（如上层指令），不走推荐。

| 步骤 | 管理员动作 | 界面响应 |
|---|---|---|
| C1 | 在列表右键 vsm-x → 「热迁移」 | 同 A2 |
| C2 | **不声明意图**（保持"未选择"），也**不点【系统推荐】**，直接在下拉里手选 node-04 | 意图控件保持空值，推荐结果区不出现；**目标节点下拉不预填，必须显式选取**——避免"看起来已选好"；无任何阻塞（R3 可跳过） |
| C3 | 选择目标存储池 pool-ssd | 存储池选项按 node-04 加载，同 A7（R8） |
| C4 | 【预检】→ 通过 | 无推荐卡片，但**六类检查仍然全部执行**——兼容性/资源/容量核算/网络落位/路径冲突/带宽，一项不减（R1/R3a/R8） |
| C5 | 【提交迁移】→ 确认 | 主弹窗关闭、进度弹窗出现（同 A14） |
| C6 | 到日志中心查看，该次迁移意图写入提交迁移记录的原因字段，显示"未声明" | R16 |

> **剧本设计意图**：手选路径必须证明"推荐不是必经关卡"。推荐只是帮用户在合格节点里挑，硬过滤的结论在手选路径下由预检完整承载。

## 场景D：推荐失败（意图推荐的核心价值演示线）

**背景设定**：管理员意图"设备升级维护"，但集群中无任何节点满足硬过滤条件。

| 步骤 | 管理员动作 | 界面响应 |
|---|---|---|
| D1–D3 | 同 A1–A3，意图选"设备升级维护" | —— |
| D4 | 点击【系统推荐】 | 推荐阶段执行硬过滤，候选为空 |
| D5 | 查看结果 | **推荐失败面板**（§3.3）出现在候选卡片本该出现的位置：红色标题"无可用目标节点"，逐节点列出淘汰原因——<br>· node-02：目标节点不存在同名交换机 sw-caiwu（10.0.1.0/24）<br>· node-03：目标存储池 pool-ssd 可用空间不足（需 60 GiB，可用 20 GiB）<br>· node-04：CPU 型号不兼容（AMD EPYC 9654 vs Intel Xeon 6338） |
| D6 | 查看建议动作 | 面板下方给出："建议：① 在 node-02 创建同名交换机与安全组后重试；② 或清理 node-03 存储池空间" |
| D7 | 查看后续可用操作 | 目标节点仍可下拉开手选（兜底路径不被堵死），但【预检】【提交迁移】在未选节点/存储池前保持置灰；若手选 node-03，预检会在"磁盘容量核算"项给出同一阻断结论 |

**剧本设计意图**：这是意图推荐真正的价值所在——**不是帮用户在好节点里挑最优，而是明确排除根本不可行的节点并说清原因**。逐节点归因比一句"迁移失败"有用得多。同时失败发生在**选节点阶段**，用户还没有在不可用的节点上白选过存储池。

## 剧本 → 界面区块的推导（第三步输入）

三个场景跑完，界面需要承载的全部元素自然浮现：

```
VSM 列表页（vm-manage，现有）
└─ 行右键菜单 + 「热迁移」项                         ← 入口（场景A A1–A2、场景C）
    └─ 热迁移主弹窗
       ├─ VSM 只读信息条（右键选定，不可改选，含磁盘总量）← C1
       ├─ 迁移意图（单选，默认"未选择"可跳过）        ← R3
       ├─ 目标节点下拉（默认空，不预填）+ [系统推荐]按钮 ← R3
       ├─ 迁移模式（单选，运行态默认热迁移）           ← R4
       ├─ 带宽限速（开关+数值框）                     ← R5
       ├─ 目标存储池（必填，选项随已选节点加载，未选节点时禁用）← R8
       ├─ 高级项折叠（CPU 节流）
       ├─ [系统推荐] [预检] [提交迁移] [取消]           ← R1/R3
       ├─ 候选节点卡片区（场景A A4–A6、场景D）         ← R3/R3a/R8
       │   ├─ 抬头"系统推荐 N 个候选节点（按 XX 意图排序）"
       │   ├─ 候选卡 × N：节点名+首选标签 / 存储池徽章 / 资源余量 / 网络落位 / 意图理由 / [选择此节点]
       │   └─ 推荐失败面板（逐节点淘汰原因 + 建议动作）  ← R3/R3a/R8
       ├─ 预检报告区（场景A A8–A10、场景C C4）        ← R1
       │   └─ 六类检查：兼容性/资源/磁盘容量/网络落位/路径冲突/带宽
       ├─ 提交二次确认弹窗（含磁盘复制量与网络落位结果）
       └─ 迁移进度弹窗（场景A A14–A19、场景B）
           ├─ 阶段指示器                             ← R9
           ├─ 实时数据（复制量/速率/预计剩余）          ← R9
           ├─ 风险告警条+建议动作按钮                  ← R10
           ├─ [取消迁移]（二次确认，含临时磁盘清理说明）  ← R11
           └─ 结果验证卡（五项：状态/IP/探活/磁盘落位/对外端口）← R14
               └─ 【查看操作日志】跳日志中心（预置筛选）← R16
```

**关于目标交换机 / 安全组**：不作为用户控件。二者是节点本地资源，由系统自动匹配（交换机：名称 + CIDR；安全组：名称）——**推荐阶段**用它判定候选是否可行（不可行则该节点不进候选），**预检阶段**再对已选节点复核并作为"网络落位"检查项展示；匹配失败即阻断并提示补齐目标节点资源（R3a）。

补充：本次**不设计**的部分——日志中心"操作日志"标签为现有页面（R16 记录写入该处，演示时以跳转/截图说明即可），VSM 列表页本身为现有页面（仅新增一个右键菜单项）。新增设计工作量 = 两个弹窗。

## 待确认问题（交导师前需要定的三条）

1. **运行中 VSM 是否允许选"冷迁移"？** 剧本 A12 现设计为"允许但弹中断提示二次确认"。备选：直接禁用冷迁移选项。涉及安全取舍，建议交导师定。
2. **网络落位匹配失败的处置**：现设计为"阻断 + 提示在目标节点补齐同名交换机/安全组"。备选：在推荐失败面板中提供"在目标节点创建同名交换机"的一键操作入口（涉及跨节点写操作，风险较高）。建议保持只提示、不代建。
3. **候选节点数量上限**：现设计为"展示前 2–3 个"。若集群规模较大（>10 节点），是否需要"展开全部合格节点"入口？建议原型阶段固定 3 个，避免列表过长冲击主表单。
